# Nexus OS — правила работы в этом репозитории

Личная операционная система фаундера: FastAPI-бэкенд + React-фронтенд +
Telegram-бот Hermes. Хранилище — JSON-файлы в `~/.nexsys`, не база данных.

## Запуск и проверка

```bash
make dev          # бэкенд :8420 с автоперезагрузкой + фронтенд :5173
make test         # весь backend/tests
```

**Бэкенд, поднятый через `start_all.ps1`, идёт БЕЗ `--reload`.** Правки в
Python-коде он не подхватит — при живой проверке через браузер его нужно
перезапускать вручную, иначе видно старое поведение и легко полдня искать
несуществующий баг.

Один uvicorn-worker обязателен: JSON-хранилище и APScheduler не переживут
конкурентных писателей.

## Несколько сессий в одном дереве — главный источник аварий

Фаундер часто ведёт две-три сессии Claude Code по этому проекту
одновременно, **в одном и том же рабочем каталоге**. Это уже приводило к
потере авторства: 24.08.2026 одна сессия сделала `git add -A` и утащила в
свой коммит незакоммиченные файлы чужой сессии.

**Правила, обязательные к соблюдению:**

1. **Никогда не делать `git add -A` / `git add .` / `git commit -a`.**
   Только явные пути: `git add backend/services/foo.py backend/tests/test_foo.py`.
2. **Перед любым коммитом — `git status`.** Увидели изменённые файлы, к
   которым вы не притрагивались, — значит рядом работает другая сессия.
   Не трогать их и не коммитить.
3. **Перед началом работы — тоже `git status`.** Если нужные вам файлы уже
   изменены кем-то другим, сначала сказать об этом фаундеру, а не
   редактировать поверх: правки перетрут друг друга.
4. Файлы, вокруг которых сессии сталкиваются чаще всего:
   `backend/models/schemas.py`, `backend/services/conversation.py`,
   `backend/main.py`, `frontend/src/App.tsx`,
   `frontend/src/components/Sidebar.tsx`, `frontend/src/lib/api.ts`.

Надёжнее всего — не вести параллельные сессии по одному проекту. Если это
всё же нужно, каждой сессии стоит дать свой git worktree.

## Ответы языковой модели разбирает `backend/core/llmjson.py`

Модель просят вернуть чистый JSON, а она отвечает как умеет: оборачивает в
` ```json `, добавляет «Конечно! Вот результат:», прячет массив под ключом,
который придумала на ходу, а единственный элемент отдаёт голым объектом
вместо массива из одного.

Раньше каждый модуль разбирал ответ сам и знал только те капризы, на
которых обжёгся лично, — один и тот же баг ловили по три раза в разных
местах. Теперь знание одно на всех.

**Никогда не писать свой разбор ответа модели.** Брать:

```python
from ..core import llmjson

data = llmjson.parse_object(raw)                      # ждём объект
items = llmjson.parse_list(raw, item_hint="topic")    # ждём список
data = llmjson.object_or({}, raw)                     # фон: не падать
```

`item_hint` — имя поля, по которому узнаётся одиночный элемент, отданный
без массива вокруг. Разбор поднимает `LLMJsonError`; молча возвращать
пустоту нельзя — она неотличима от «модели нечего сказать».

Исключение: `services/tools.py` разбирает SSE-поток и аргументы вызова
инструментов — это строгий JSON по контракту API, а не вольный ответ.

## Тесты проходят ≠ работает

Три подряд случая (23–24.08.2026), когда зелёные тесты пропускали баг,
который вылезал на первой же живой проверке: разбор голосовой команды,
медиа-теги без токена, три разные формы ответа модели.

**Любую фичу, которая ходит в модель, в сеть или в браузер, обязательно
проверять вживую** — через настоящий API или через браузер, а не только
юнит-тестами. Тестовые данные после проверки удалять: очередь фаундера
должна оставаться чистой.

Отдача медиа браузерному тегу (`<img>`, `<audio>`, `<video>`) требует
токена в строке запроса — заголовок `Authorization` теги слать не умеют,
браузер получит 401 и покажет пустоту.

## Прочее

- `LLMService()` без аргументов берёт `NEXSYS_LLM_PROVIDER=ollama` из
  `.env`, а локальный Ollama на машине не поднят. Всегда указывать
  провайдера явно: `LLMService(provider="deepseek", model="deepseek-chat",
  api_key=settings.deepseek_api_key)`.
- Комментарии в этом проекте объясняют **почему**, а не что. Много ссылок
  на конкретные даты и находки — так и надо, это память проекта.
- Экраны — карточки в теме Пантеона (`frontend/src/styles/pantheon.css`,
  классы `.n-card`/`.n-grid`/`.n-badge`). Не выдумывать оформление заново.
- Пустой экран почти всегда означает проглоченную ошибку, а не отсутствие
  данных. Различать «загружаю», «ошибка» и «действительно пусто».
