# Продакшн-команда — семь агентов в Telegram

Что это: семь ролей, каждая — настоящий агент с инструментами, своей файловой песочницей и памятью на диске. Работу друг другу передают файлами. Вход — ссылка на сайт бренда. Выход — production pack, из которого собирается рекламный ролик.

Это отдельный пакет. `backend/services/agent_engine.py` и фоновые работники Nexus OS (Строитель, Библиотекарь, Рецензент, Исследователь, Монитор, Куратор, Джарвис) не затронуты.

## Роли

| Имя | Ключ | Что делает | Кому передаёт |
|---|---|---|---|
| Маркетолог | `marketer` | Разбор бренда, конкурентов, аудитории | Сценарист, Продюсер |
| Сценарист | `screenwriter` | Идеи роликов, раскадровка | Промпт-инженер, Звукорежиссёр, Продюсер |
| Промпт-инженер | `prompt_engineer` | Character Bible, покадровые промты, генерация кадров | Продюсер |
| Звукорежиссёр | `sound` | Музыка, голос, точки монтажа | Продюсер |
| Продюсер | `producer` | Приёмка и финальный пакет | — конец цепочки |
| Скаут | `scout` | Поиск клиентов | Маркетолог |
| Секретарь | `secretary` | Реестр проектов, «что где стоит» | — |

## Запуск

### 1. Токены ботов

Нужны боты в [@BotFather](https://t.me/BotFather) — по одному на роль, чтобы в списке чатов они выглядели отдельными собеседниками. Это единственный шаг, который нельзя сделать за тебя: боты создаются с твоего аккаунта Telegram.

В BotFather: `/newbot` → имя (например «Маркетолог») → username (например `my_crew_marketer_bot`) → получишь токен.

Токены положи в `.env`:

```
CREW_TOKEN_MARKETER=...
CREW_TOKEN_SCREENWRITER=...
CREW_TOKEN_PROMPT_ENGINEER=...
CREW_TOKEN_SOUND=...
CREW_TOKEN_PRODUCER=...
CREW_TOKEN_SCOUT=...
CREW_TOKEN_SECRETARY=...
```

**Попробовать до того, как заводить семь ботов:** создай одного и положи его токен в `CREW_TOKEN_ALL`. Тогда поднимется один бот на всю команду, роль переключается командой `/role marketer`. Всё остальное работает так же.

Не используй токен Hermes: два процесса на одном токене конфликтуют, и оба перестанут получать сообщения.

### 2. Доступ

```
TELEGRAM_ALLOWED_USER_ID=123456789
```

Числовой id, не username. Узнать свой — написать [@userinfobot](https://t.me/userinfobot).

Без этой переменной запуск останавливается намеренно: бот в Telegram открыт всему интернету, и агент с файловыми инструментами не должен отвечать кому попало. Несколько id — через запятую.

### 3. Движок

**Настроен и проверен живым прогоном 6 сентября 2026: DeepSeek отвечает, инструменты вызываются, файл на диске.** Ничего делать не надо.

Команда берёт движок отдельно от остального Nexus OS. Причина: в `.env` стоит `NEXSYS_LLM_PROVIDER=ollama`, и переключать это глобально значило бы сменить движок всем персонам Пантеона разом. Команде нужна модель посильнее локальной 8B, остальному — как настроено.

По умолчанию — DeepSeek, ключ берётся из `DEEPSEEK_API_KEY`. Переопределяется:

```
CREW_LLM_PROVIDER=deepseek     # или openai, или ollama
CREW_LLM_MODEL=deepseek-chat
```

Замеченное по дороге, к сведению: `backend/core/config.py:57` читает ключ движка **только** из `NEXSYS_LLM_API_KEY`, а реальные ключи лежат в `.env` под короткими именами (`DEEPSEEK_API_KEY` и другие). То есть общий движок Nexus OS их не видит, хотя они на месте. В том же файле есть хелпер `env_any`, написанный ровно против этой болезни, но к главному движку он не применён. Команда обходит это сама; в остальном проекте — не трогал.

### 4. Сертификаты — это уже сделано, но знать надо

На этой машине **Avast перехватывает TLS** и подменяет сертификаты своим корнем. Он лежит в хранилище Windows, поэтому браузер и `curl` работают, а Python — нет: у него свой бандл `certifi`, и любой HTTPS-вызов падает с `CERTIFICATE_VERIFY_FAILED`. Симптом при этом выглядит как «модель недоступна» и уводит искать причину не там.

Вылечено пакетом `truststore` (добавлен в `requirements.txt`), который переключает проверку на системное хранилище Windows. Проверка сертификатов при этом остаётся включённой.

**Это касается не только команды.** Тем же самым сломаны любые HTTPS-вызовы из Python в этом проекте — fal.ai, Firecrawl, ElevenLabs. Я поправил только `crew/`; если где-то ещё «сервис не отвечает» без внятной причины — причина, скорее всего, здесь.

### 5. Ключи, которые уже есть

`FAL_KEY` (генерация кадров) и `FIRECRAWL_API_KEY` (веб-поиск) уже настроены — отдельно ничего делать не надо.

### 6. Старт

```bash
python -m crew.bot
```

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `NEXUS_CREW_ROOT` | `<проект>/crew_workspaces` | Корень песочниц |
| `NEXUS_CREW_MAX_ITERATIONS` | 60 | Потолок обращений к инструментам за прогон |
| `NEXUS_CREW_MAX_SECONDS` | 900 | Потолок времени на прогон |
| `NEXUS_CREW_MAX_RUN_USD` | 1.50 | Потолок расходов на прогон |

Три потолка — не перестраховка. Агент без них способен разбирать один бренд часами: это не гипотеза, автор системы-прототипа жалуется на это прямым текстом.

## Как этим пользоваться

Типичный проект:

1. **Маркетологу:** «разбери бренд monsheri.ru» → он читает сайт, ищет упоминания, пишет `analysis.md`.
2. `/project monsheri` — закрепить ключ проекта в чате.
3. **Маркетологу:** «передай Сценаристу» → жмёшь ✅ на кнопке подтверждения.
4. **Сценаристу:** «что мне передали?» → он находит передачу сам. Дальше: «собери три идеи».
5. Выбираешь идею → «разверни первую в раскадровку» → «передай Промпт-инженеру, приложи разбор бренда».
6. **Промпт-инженеру:** «собери пакет промптов» → Character Bible → карточка героя → кадры. Кадры приходят прямо в чат.
7. **Продюсеру:** «собери финальный пакет» → приёмка и статус.
8. Финальное видео собираешь сам: берёшь промты из `final-prompts.md` и кадры из `docs/frames/`, вставляешь в Seedance или Kling.

Команды в любом чате: `/project`, `/inbox`, `/files`, `/team`, `/forget`.

## Что где лежит

```
crew_workspaces/
  marketer/workspace/docs/research/<slug>/analysis.md
  screenwriter/workspace/docs/creative/<slug>/storyboard.md
  prompt_engineer/workspace/docs/prompts/<slug>/character-bible.md
  prompt_engineer/workspace/docs/frames/<slug>/shot-01.jpg
  producer/workspace/docs/final-production/<slug>/
```

Раскладка намеренно повторяет `/srv/hermes-<role>/workspace/`. Появится сервер — переезд делается `rsync`, а не переписыванием путей: `NEXUS_CREW_ROOT=/srv/hermes`.

## Границы, которые держат

Проверено внешним аудитом с прогоном реальных эксплойтов на этой машине, не на словах.

- **Песочница.** Роль читает и пишет только свою папку. Отвергаются `../`, абсолютный путь, `~`, `C:x`, `\\?\`, `nul`/`CON`, альтернативные потоки данных, папка другой роли.
- **Поиск не выходит за песочницу.** `..` в глобе и абсолютные пути в шаблоне отвергаются, результат дополнительно фильтруется по факту. *Аудит нашёл здесь рабочий эксплойт: `*/../../../producer/workspace/docs/*` перечислял файлы чужой роли. Закрыто, есть тест.*
- **Поиск по содержимому не читает закрытое.** `.git/config` с токеном в URL находился грепом, хотя `read_file` его не отдавал. Теперь фильтр по расширению и по имени родительской папки. *Закрыто, есть тест.*
- **Белый список инструментов.** Инструмент, не выданный роли, не попадает в запрос к модели вовсе, и отвергается при вызове. Двойная проверка.
- **Подтверждение человеком.** `terminal` и `submit_handoff` спрашивают каждый раз, без «запомнить». Список вложений показывается целиком. Нет способа спросить, отправка запроса упала, истёк таймаут — всё это отказ, а не молчаливое разрешение.
- **Секреты не в песочнице.** `.env`, `credentials.json`, `*.pem`, `*.key`, `.git` закрыты и для чтения, и для поиска.
- **Нет хода во внутреннюю сеть.** `fetch_url` отвергает loopback, приватные и link-local адреса, редиректы проверяются на каждом шаге. *Без этого агент дотягивался до `127.0.0.1:8000` — локального API проекта, где нет авторизации и живут почта, кошелёк и документы.*
- **Недоверенный текст в явной границе.** Сайты, выдача поиска и передачи от других агентов приходят в `<untrusted src="...">…</untrusted>`, закрывающий тег внутри тела экранируется. Плюс инвариант: из недоверенного текста нельзя брать ключ проекта, имя файла, путь, получателя передачи и контакт.
- **Наружу никто не пишет.** Ни в канал, ни клиенту, ни на почту. Выносит человек.

## Чего эти границы не закрывают

Честно, чтобы не было иллюзий.

- **`terminal` у Продюсера — это полный доступ к машине под твоей учётной записью после одного «Разрешить».** Рабочая папка ограничена, но `cd ..\..\..` — обычная команда, а корень проекта с `.env` лежит на три уровня выше. Белый список команд здесь бесполезен: любой интерпретатор его обходит. Единственное, что реально сузило бы радиус на Windows без Docker, — отдельная учётная запись с правами только на `crew_workspaces`.
- **Потолок расходов считает только модель.** Картинки на fal.ai ограничены счётчиком (12 за прогон), а не деньгами.
- **Окно между проверкой пути и открытием файла.** Теоретически закрывается симлинком, подставленным в этот момент; практически требует уже полученного выполнения кода.
- **Prompt injection закрыт вероятностно.** Граница `<untrusted>` и инвариант сильно поднимают планку, но гарантии не дают. Гарантию даёт только то, что агент физически не может сделать: песочница, белый список инструментов и гейт подтверждения.

Если система начнёт работать с чужими деньгами или чужими данными — переносить на арендованный сервер в Docker, non-root, с ключами в отдельном прокси-сервисе. Раскладка папок к этому готова.

## Чего система не делает

- **Не генерирует видео.** Только кадры. Оживление — вручную, в Seedance или Kling. Это осознанно: видео-сервисы меняются каждые пару месяцев, а промты остаются.
- **Не маршрутизирует сама.** Кому передать, решает человек. Автономный оркестратор на этой задаче даёт не скорость, а неконтролируемые расходы.
- **Не работает мультитенантно.** Один владелец, один список разрешённых пользователей.
